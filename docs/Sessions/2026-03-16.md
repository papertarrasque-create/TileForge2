### Bugs found during testing

1. **on_pickup_dialogue missing from Item presets** -- GroupEditor Item presets didn't include `on_pickup_dialogue`. Fixed by adding it to the preset array. The property was already supported by GroupEditor's dropdown rendering and GameplayScreen's pickup flow.

2. **Entity groups invisible when map lacks matching layer** -- QuestTestMap.tileforge only had a "Ground" layer, but entity groups referenced "Entities" layer. MapPanel.cs:143 filters groups by `group.LayerName != layer.Name`, so entity groups were invisible in the sidebar. Fix: .tileforge files must include all layers referenced by their groups.

### Key spec review findings (caught before implementation)
- `has_item` condition uses `item` field, not `value` (DialogueData.cs Condition class)
- Item entities use `on_pickup_dialogue` property, not `dialogue_id` (GameplayScreen skips TryShowDialogue for Items)
- `heal` action requires an integer value string, not empty
- `CollectItem` adds DefinitionName (capital `Amulet`) to inventory -- `has_item`/`remove_item` must match case

## Session 5: Debugging & Cellar Depths Commit

### Investigated bug reports

1. **"Can't delete tile after play mode"** -- Investigated extensively. Root cause: **layer mismatch in map data**, not a play mode bug. The `HouseWallVert` tile at position (7,6) was placed on the Ground layer, but the active layer was Walls. The eraser operates on the active layer only, so it saw a null cell and did nothing. The same tile at (7,5) was correctly on the Walls layer and could be deleted. Resolution: switch to Ground layer to erase.

2. **"Quest won't resolve after killing rats and collecting amulet"** -- Root cause: **item name mismatch**. The amulet entity group is named `Amulet2`, so `CollectItem` adds "Amulet2" to inventory. But sage_01.json's `return_amulet` route checks `has_item: "Amulet"` (without the "2"). The condition never matches. User fixed in-editor.

### Minor finding (not fixed)

- **UndoStack event wiring stale after play mode revert** -- `PlayModeController.Exit()` restores MapDocuments from deep copies, but `ActiveMapIndex` setter early-returns when the index hasn't changed. This skips `WireUndoStack()`, leaving the `_wiredUndoStack.StateChanged` subscription pointing to the old (dead) UndoStack. Consequence: `MarkDirty()` and `UndoRedoStateChanged` events don't fire from undo operations after revert. Functional impact is low (dirty tracking only), but should be fixed.
