# Session: 2026-03-17

## Property Schema Registry

Addressed the "property bags are stringly typed" architectural concern. Entity properties remain `Dictionary<string, string>` for serialization, but all access now goes through a centralized schema system.

### What was built

- **PropertyKeys** -- 30+ `const string` fields replacing all raw string literals. Typos are now compile errors.
- **PropertyDef + IntRange** -- Schema entry defining key, type (Int/Bool/Enum/MapRef/DialogueRef/String), constraints, and applicable entity types.
- **PropertySchema** -- Static registry of all property definitions with `Get()`, `ForEntityType()`, `IsKnown()` lookup helpers.
- **PropertyAccess** -- `GetInt`, `GetBool`, `GetString`, `SetInt` typed helpers replacing scattered `TryGetValue` + `int.TryParse` patterns (~25 call sites).
- **PropertyValidator** -- Load-time validation on play-mode enter. Errors (type mismatch, out of range) logged in red; warnings (unknown properties) in yellow.
- **GroupEditor migration** -- `Presets` and `NumericSpecs` dictionaries replaced by `PropertySchema.ForEntityType()` queries. `CreatePropField` now uses `PropertyDef.Type` switch instead of key-name if/else chain. Net -15 lines.

### Files changed

**New (5+4 test):** PropertyKeys.cs, PropertyDef.cs, PropertySchema.cs, PropertyAccess.cs, PropertyValidator.cs + corresponding test files (47 new tests).

**Modified (7):** EntityAI, GameStateManager, GameplayScreen, TriggerManager, MapCanvas, InventoryScreen, GroupEditor. Also IProjectContext and 4 test files for remaining raw string cleanup.

### Key decisions

- Keep `Dictionary<string, string>` everywhere (no serialization changes, no migration)
- Unknown properties warn but don't block (extensibility preserved, path to strict mode later)
- `dialogue` property typed as `DialogueRef` (matches existing editor dropdown behavior)
- `max_health` and `xp` now appear in GroupEditor for NPC/Trap (previously runtime-only)
- `AppliesTo` validation deferred (EntityInstance doesn't carry EntityType at runtime)

### Test impact

1681 -> 1728 tests (47 new). 0 failures.

## Combat Knockback System

Addressed the "Combat pace redesign" item from Status.md. Current spam-bump was too fast -- player could hit enemies twice per turn with no positioning cost.

### What was built

- **KnockbackResolver** -- Static pure class (follows EntityAI pattern). Determines if a defender should be pushed back 1 tile after being hit, based on weight and accumulated hits this turn.
- **KnockbackResult** -- Readonly struct returned by resolver (KnockedBack, NewX, NewY).
- **Weight system** -- Entity property `weight` (1-3, default 1) controls knockback resistance. Requires N hits in a single turn to push. Weight 1 = knocked back every hit. Weight 2 = needs cornering or 2+ AP. Weight 3 = effectively immovable.
- **Player weight** -- Base weight on PlayerState (default 1) + `equip_weight` equipment modifier via `GetEffectiveWeight()`.
- **HitsThisTurn stagger tracking** -- Dictionary on PlayState, cleared per-turn (player) and per-entity (entity sub-turns). Each entity's stagger is independent.
- **Symmetric knockback** -- Same rules apply to player-attacks-entity and entity-attacks-player. Getting cornered is dangerous for both sides.
- **IsTileWalkableAndUnoccupied** -- Helper for knockback destination validation (map bounds, tile solidity, entity solidity, player occupancy).

### Pacing impact

- vs Weight-1 (open): 1 attack per turn (bump + chase = 2 AP)
- vs Weight-2 (open): 2 attacks per turn, knockback on 2nd hit
- vs Weight-2 (cornered): 2 attacks, knockback blocked by wall (positional reward)
- vs Weight-3+: Stand-and-trade (effectively immovable)

### Files changed

**New (3):** KnockbackResolver.cs, KnockbackResolverTests.cs, KnockbackIntegrationTests.cs

**Modified (6):** PropertyKeys.cs, PropertySchema.cs, PlayerState.cs, PlayState.cs, GameStateManager.cs, GameplayScreen.cs

### Key decisions

- Defender gets knocked back (not attacker recoil)
- Blocked knockback has no extra effect (no wall damage)
- Stagger resets each turn (not persistent across turns)
- No hazard tile interaction on knockback
- Kill skips knockback
- Entity-vs-entity knockback out of scope

### Test impact

1728 -> 1757 tests (29 new: 12 unit + 17 integration). 0 failures.

## Entity Animation System

Added hop (parabolic arc) animation for player movement and fast slide-back animation for knockback, replacing instant teleports with smooth motion.

### What was built

- **EntityAnimator** -- Pure C# animation manager keyed by entity ID. Two types: HopMove (linear lerp + parabolic Y offset, 0.15s base) and SlideBack (linear lerp, 0.08s). Supports completion callbacks, animation replacement (old callback discarded), and Clear().
- **GameplayScreen integration** -- Manual player movement lerp replaced with `_animator.StartHop()`. Post-move logic extracted to `OnPlayerMoveComplete()` callback. Both player and entity knockback use `_animator.StartSlideBack()`.
- **MapCanvas integration** -- Optional `EntityAnimator` parameter threaded through Draw/DrawEntities. Entity knockback slides render at animated positions with culling skip.
- **PlayState cleanup** -- Removed `IsMoving`, `MoveFrom`, `MoveTo`, `MoveProgress`, `MoveDuration`, `CurrentMoveDuration`. Retained `RenderPos` as write-through from animator.

### Key decisions

- Write-through pattern: GameplayScreen updates `PlayState.RenderPos` each frame from the animator. Minimap, camera, PlayModeController unchanged.
- Player-only scope: NPC movement stays instant. Extending to NPC hops requires async `ExecuteEntityTurn` (deferred).
- Camera follows the hop arc vertically (slight bob during movement) -- intentional lively feel.
- Player knockback slide has completion callback to snap RenderPos; entity knockback has none (SyncEntityRenderState runs every frame).

### Files changed

**New (2):** EntityAnimator.cs, EntityAnimatorTests.cs (11 tests)
**Modified (4):** GameplayScreen.cs, MapCanvas.cs, PlayState.cs, PlayModeControllerTests.cs (~27 edits), APCombatTests.cs (1 edit)

### Test impact

1757 -> 1768 tests (11 new). 0 failures.
